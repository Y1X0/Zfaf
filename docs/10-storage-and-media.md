# 10 — Storage & Media Architecture

**الإصدار:** v0.1 · **الحالة:** Draft

---

## 1. المبادئ

1. **لا bytes في PostgreSQL.** قاعدة البيانات تحمل الميتاداتا فقط.
2. **الملف لا يمرّ عبر خادم التطبيق.** رفع مباشر إلى التخزين بروابط موقّعة.
3. **لا تثق بالعميل.** لا في `Content-Type`، لا في الامتداد، لا في الحجم المُعلَن.
4. **الوسائط تُخدَم من نطاق منفصل** لتقليل أثر أي ثغرة عرض محتوى.
5. **الأصل غير قابل للتغيير.** التعديلات تنتج أصولاً جديدة (مهم للـ cache وللنسخ المنشورة).

## 3. تنظيم الحاويات

| الحاوية | الوصول | المحتوى |
|---------|--------|---------|
| `zfaf-media` | خاصة → CDN عبر worker | صور المستخدمين ونسخها |
| `zfaf-public` | عامة | أصول القوالب، الزخارف، صور OG |
| `zfaf-audio` | خاصة → CDN | مكتبة الموسيقى المرخّصة |
| `zfaf-quarantine` | خاصة تماماً | ملفات مشبوهة بانتظار الفحص |
| `zfaf-backups` | خاصة تماماً | نسخ احتياطية |

### مخطط المفاتيح

```
media/{ownerId}/{invitationId}/{mediaId}/original.{ext}
media/{ownerId}/{invitationId}/{mediaId}/w400.avif
media/{ownerId}/{invitationId}/{mediaId}/w1080.avif
media/{ownerId}/{invitationId}/{mediaId}/w1920.avif
media/{ownerId}/{invitationId}/{mediaId}/w1080.webp
media/{ownerId}/{invitationId}/{mediaId}/w1080.jpg
og/{invitationId}/{versionHash}.png
audio/library/{trackId}/{trackId}.m4a
```

**قواعد المفاتيح:**
- **اسم الملف الأصلي لا يظهر في المفتاح أبداً.** أسماء الملفات مصدر شائع لهجمات
  اجتياز المسار وحقن الترميز. نحتفظ به في DB للعرض فقط.
- المسار يتضمن `ownerId` → تدقيق أسهل وحذف جماعي عند حذف الحساب.
- `versionHash` في مفاتيح OG → تخزين دائم غير قابل للتغيير.

## 4. تدفق الرفع الآمن

### المرحلة ① — طلب رابط رفع

```
POST /api/v1/media/upload-url
{ kind:"image", purpose:"gallery", invitationId:"...",
  filename:"IMG_1234.HEIC", contentType:"image/heic", sizeBytes:4200000 }
```

**تحقق الخادم:**
```
✓ الفاعل يملك الدعوة
✓ contentType ضمن القائمة البيضاء للغرض
✓ sizeBytes ضمن الحد
✓ حصة التخزين لم تُستنفد (الباقة)
✓ عدد الملفات لم يتجاوز الحد
✓ حد المعدل (60 رفع/ساعة)
```

```json
{ "mediaId":"...", "uploadUrl":"https://…r2…?X-Amz-…",
  "expiresIn":900,
  "requiredHeaders": { "Content-Type":"image/heic", "Content-Length":"4200000" } }
```

**الرابط الموقّع مقيّد بـ:** الطريقة (`PUT` فقط) · المفتاح المحدد · `Content-Type` · `Content-Length`
· صلاحية 15 دقيقة.

⚠️ **مهم:** بلا تقييد `Content-Length` في التوقيع، يستطيع العميل رفع 5GB برابط طُلب لـ 4MB.

### المرحلة ② — الرفع المباشر
`PUT <uploadUrl>` من المتصفح إلى R2. لا يلمس خادمنا.

### المرحلة ③ — التأكيد

```
POST /api/v1/media/{mediaId}/complete
```
الخادم يستدعي `HEAD` على R2 للتأكد من: وجود الكائن، الحجم الفعلي، `ETag`.
**لا يثق بادعاء العميل.** ثم يضع المهمة في الطابور.

### المرحلة ④ — المعالجة (worker)

```
1. تنزيل إلى مساحة معزولة
2. ✅ تحقق magic bytes  ← الأهم أمنياً
      JPEG  FF D8 FF
      PNG   89 50 4E 47 0D 0A 1A 0A
      WebP  52 49 46 46 … 57 45 42 50
      AVIF  … 66 74 79 70 61 76 69 66
      HEIC  … 66 74 79 70 68 65 69 63
      ❌ عدم التطابق ⇒ حجر + رفض
3. ❌ رفض قاطع: SVG (يمكن أن يحمل JS) · TIFF · أي شيء خارج القائمة البيضاء
4. تحقق الأبعاد: ≤ 12000×12000، ونسبة أبعاد معقولة  ← ضد قنابل الضغط
5. تحقق حدود فك الضغط (`Sharp.limitInputPixels`)  ← ضد decompression bombs
6. 🔒 تجريد كل الميتاداتا:
      EXIF (يحتوي GPS! اسم الجهاز! التاريخ!)
      IPTC · XMP · ICC (عدا تحويل مساحة اللون)
7. إعادة الترميز الكاملة  ← أقوى دفاع: يدمّر أي حمولة مضمّنة
8. توليد النسخ: w400 / w1080 / w1920 بصيغ AVIF + WebP + JPEG
9. توليد blurhash
10. فحص برمجيات خبيثة (§7)
11. رفع النسخ إلى R2
12. تحديث DB: status=ready, variants, blurhash, width, height
```

> **الخطوة 6 ليست تفصيلاً.** صور الهواتف تحمل إحداثيات GPS دقيقة.
> نشر صورة العروسين بلا تجريد EXIF = نشر عنوان منزل العائلة. هذا تسريب خصوصية حقيقي وخطير.

> **الخطوة 7 (إعادة الترميز) هي خط الدفاع الأقوى.** حتى لو تسللت حمولة خبيثة داخل ملف صورة صالح،
> فك الترميز وإعادة الترميز عبر Sharp يُنتج ملفاً جديداً بالبكسلات فقط.

## 6. الخدمة والتخزين المؤقت

```
GET https://cdn.zfaf.app/media/{owner}/{inv}/{mediaId}/w1080.avif
```

- نطاق منفصل (`cdn.zfaf.app`) — بلا كوكيز، وعزل عن نطاق التطبيق.
- `Cache-Control: public, max-age=31536000, immutable` — الأصل غير قابل للتغيير.
- Cloudflare Worker يترجم من الرابط العام إلى R2 ويفرض الضوابط.

**ترويسات أمنية على نطاق الوسائط:**
```
Content-Type: image/avif                (صريح — من DB لا من الملف)
X-Content-Type-Options: nosniff
Content-Disposition: inline
Content-Security-Policy: default-src 'none'; sandbox
Cross-Origin-Resource-Policy: cross-origin
```

**لماذا `default-src 'none'; sandbox` على الوسائط؟** لو تسلل ملف قابل للتنفيذ كـ HTML رغم كل الطبقات،
هذه الترويسة تمنعه من فعل أي شيء. حزام وحمّالة.

### الوصول الخاص
المسودات والمعاينات: روابط موقّعة قصيرة العمر (5 دقائق)، بلا cache على CDN.

## 7. فحص البرمجيات الخبيثة

**تقييم صادق للمخاطر:** خطر الفيروسات في الصور المعاد ترميزها **منخفض جداً**.
إعادة الترميز الكاملة تدمّر عملياً أي حمولة. لكن نبني البنية للمستقبل (رفع الصوت، وملفات أخرى لاحقاً).

```
Phase 1:  إعادة ترميز + تحقق magic bytes + حدود صارمة     ← كافٍ للصور
Phase 2:  ClamAV في الـ worker لكل ما ليس صورة معاد ترميزها
Phase 3:  خدمة فحص خارجية عند التوسع
```

الواجهة موجودة من الآن:
```typescript
interface MalwareScanner {
  scan(key: StorageKey): Promise<{ clean: boolean; threat?: string }>;
}
// Phase 1: NoOpScanner للصور المعاد ترميزها (مع تسجيل صريح)
```

**عند اكتشاف تهديد:** نقل إلى `zfaf-quarantine` · `scan_status='infected'` · تعطيل الأصل
· تنبيه الأمن · مراجعة حساب المستخدم.

## 8. الموسيقى — الجانب القانوني

⚠️ **هذا أكبر خطر قانوني في المنتج.**

نشر موسيقى محمية بلا ترخيص على منصة تجارية يعرّضنا لمطالبات مباشرة.
الأسوأ: المستخدم قد يرفع أغنية شهيرة ظناً أنه «استخدام شخصي» — والمسؤولية علينا كناشر.

### الاستراتيجية

**Phase 1 — مكتبة منسّقة فقط. لا رفع إطلاقاً.**

| المصدر | الترخيص | الحالة |
|--------|---------|--------|
| Creative Commons (CC0 / CC-BY) | حر مع نسب | ✅ |
| موسيقى بلا حقوق (Public Domain) | حر | ✅ |
| ترخيص تجاري مدفوع (Artlist/Epidemic) | مرخّص | ✅ مع توثيق |
| تكليف موسيقيين محليين | ملكية كاملة | ✅ **الأفضل استراتيجياً** |
| YouTube / Spotify / أي أغنية تجارية | ❌ | **ممنوع قطعياً** |

**تكليف موسيقي عربي بإنتاج 8–12 مقطعاً أصلياً** (~$1500–4000 مرة واحدة) يحلّ المشكلة نهائياً،
ويعطينا تمايزاً: موسيقى لا توجد على أي منصة أخرى.

**لكل مقطع في `music_tracks`:**
```
license_type · license_url · license_proof_url  ← ملف الترخيص/الفاتورة مؤرشف
attribution_required · attribution_text
```
📄 [ADR-0012](adr/0012-licensed-music-library.md)

### Phase 2 — رفع مقيّد

عند السماح بالرفع (للباقات المدفوعة):
```
☑ أقرّ بأنني أملك حقوق هذا المقطع أو لدي ترخيص لاستخدامه
   (مربع إلزامي + تسجيل الإقرار في audit_logs مع الطابع الزمني و IP hash)
```
+ إجراء DMCA موثّق + آلية بلاغ ظاهرة + إزالة سريعة عند الشكوى + سياسة المخالف المتكرر.

**ملاحظة:** الإقرار يقلّل المسؤولية لكنه لا يلغيها. لذلك تبقى المكتبة المنسّقة هي المسار الافتراضي
والموصى به بقوة في الواجهة.

## 9. الحصص وجمع القمامة

### تتبع الاستخدام
عمود `storage_used_bytes` على `users`، يُحدَّث عند اكتمال المعالجة والحذف،
مع مطابقة يومية مقابل مجموع `media_assets` (كشف الانحراف).

### حذف الأصول

```
حذف الوسيط
   │
   ├─ ⚠️ فحص: هل هو مستخدم في أي invitation_version منشورة؟
   │      نعم → رفض: «هذه الصورة مستخدمة في دعوة منشورة»
   │      لا  → deleted_at = now()  (حذف ناعم)
   │
   └─ بعد 7 أيام → المهمة الدورية تحذف من R2 نهائياً
```

**سبب فحص النسخ المنشورة:** بدونه، مستخدم ينظّف مكتبته فيكسر دعوة منشورة يراها 300 ضيف.
هذا سيناريو حقيقي جداً وضرره كبير.

### جمع القمامة اليومي
- وسائط `status='pending'` منذ > 24 ساعة (رفع لم يكتمل).
- كائنات في R2 بلا صف مقابل في DB (انحراف).
- وسائط الدعوات المحذوفة نهائياً.
- ملفات الحجر الصحي بعد 90 يوماً.

## 10. تحسين الصور

### مصفوفة النسخ

| النسخة | العرض | الاستخدام | AVIF (تقريبي) |
|--------|-------|-----------|----------------|
| `thumb` | 400px | مصغرات المعرض | ~25KB |
| `medium` | 1080px | العرض الرئيسي على الجوال | ~90KB |
| `full` | 1920px | العرض الكامل / سطح المكتب | ~220KB |

الجودة: AVIF 55، WebP 75، JPEG 82. تُقاس بصرياً ولا تُعتمد أرقاماً عمياء.

### الضغط في المتصفح قبل الرفع

```typescript
// صورة iPhone = 4–8MB. الرفع على 4G = 30–60 ثانية = مستخدم يغادر.
// الضغط قبل الرفع: 4MB → 600KB، والرفع يصبح 5 ثوانٍ.
async function compressBeforeUpload(file: File): Promise<Blob> {
  if (file.size < 1_000_000) return file;
  const bitmap = await createImageBitmap(file);
  const scale  = Math.min(1, 2400 / Math.max(bitmap.width, bitmap.height));
  const canvas = new OffscreenCanvas(bitmap.width * scale, bitmap.height * scale);
  canvas.getContext('2d')!.drawImage(bitmap, 0, 0, canvas.width, canvas.height);
  return canvas.convertToBlob({ type: 'image/webp', quality: 0.85 });
}
```

⚠️ ملاحظة: `createImageBitmap` يزيل EXIF ضمناً — لكن **الخادم يجرّده مجدداً** ولا يعتمد على العميل أبداً.

## 11. توليد صور OG

```
عند النشر → مهمة → Satori (JSX→SVG) → resvg (SVG→PNG) → R2
```
- 1200×630 بالضبط · ≤ 300KB · تخزين دائم بمفتاح يحمل hash النسخة.
- المحتوى: أسماء العروسين بخط القالب، التاريخ، ألوان القالب، شعار خفيف.
- **احتياطي فوري:** إن فشلت المهمة، تُستخدم صورة عامة للقالب — الرابط يُشارَك بمعاينة لائقة دائماً.
- ⚠️ WhatsApp لا يجلب > 600KB ولا يتبع إعادة التوجيه بشكل موثوق ⇒ رابط مباشر ومطلق و HTTPS.

## 12. التعافي والنسخ الاحتياطي

| البند | السياسة |
|-------|---------|
| R2 versioning | مفعّل — استرجاع الحذف العرضي |
| النسخ عبر مناطق | Phase 2 |
| النسخ الاحتياطي | R2 → Backblaze B2 أسبوعياً (استقلال عن المزوّد) |
| RPO للوسائط | 24 ساعة |
| RTO للوسائط | 4 ساعات |

**قرار مهم:** الوسائط المفقودة **لا تكسر الدعوة** — الـ Renderer يعرض `MissingMediaFallback`
والنص يبقى كاملاً. تدهور رشيق لا انهيار.
