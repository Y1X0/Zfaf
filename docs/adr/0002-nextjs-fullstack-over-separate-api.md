# ADR-0002 — Next.js full-stack بدل خدمة API منفصلة

**الحالة:** Proposed · **التاريخ:** 2026-08-16 · **القرار المرتبط:** #1

## السياق

طُرح في المتطلبات: `Backend: Node.js/NestJS أو FastAPI`. هذا خيار معقول لكنه يفترض
فصلاً بين الواجهة والخادم. علينا التحقق من أن هذا الفصل يخدمنا فعلاً في **هذه المرحلة**.

قيود حاسمة:
- الصفحة العامة تحتاج **SSR ممتازاً** (SEO، معاينة WhatsApp، LCP < 2s).
- نفس مكوّن `InvitationRenderer` يجب أن يعمل في **المعاينة داخل الـ Builder** و**الصفحة المنشورة**.
  لو انفصلا، تظهر فجوة «ما تراه ليس ما تحصل عليه» — وهي أكبر شكوى في منتجات مشابهة.
- عميل واحد فقط في الأفق المنظور (المتصفح).

## القرار

**تطبيق Next.js واحد (App Router) يخدم كل الأسطح**، مع **شرط معماري إلزامي**:

> كل منطق الأعمال في `packages/core`، بلا أي تبعية على Next.js أو HTTP أو Prisma.

```ts
// ✅ Route Handler نحيف — طبقة نقل فقط
export async function POST(req: Request, { params }) {
  const actor  = await requireSession(req);
  const body   = publishSchema.parse(await req.json());
  const result = await publishInvitation({ actor, invitationId: params.id, ...body }, deps);
  return toHttp(result);
}
```

سقف صريح: **أطول route handler ~25 سطراً**. أطول من ذلك = منطق تسرّب ويجب نقله.

## البدائل المرفوضة

| البديل | التكلفة | لماذا رُفض الآن |
|--------|---------|------------------|
| Next.js + NestJS | +3–4 أسابيع | قفزة شبكة إضافية، OpenAPI + codegen، CORS، مصادقة بين الخدمات — كل ذلك لخدمة عميل واحد |
| Next.js + FastAPI | +5–6 أسابيع | كل ما سبق + لغتان + بيئتان + تكرار نماذج البيانات |
| Remix / SvelteKit | — | نظام React البيئي أوسع، وRSC يعطينا ميزة أداء حقيقية على الصفحة العامة |

**ملاحظة عادلة:** لو كان لدينا تطبيق جوال أصلي مخطط له من اليوم الأول، لكان (ب) القرار الصحيح.
القرار مشروط بالسياق لا مطلق.

## العواقب

### إيجابية
- أسرع طريق لـ MVP · مشاركة الأنواع بلا codegen · Renderer مشترك يضمن صدق المعاينة
· RSC يقلل JS على الصفحة الحرجة · خدمة واحدة تُنشر وتُراقَب.

### سلبية
- بنية الخادم (DI، الوحدات، الحراس) نبنيها يدوياً بدل الحصول عليها جاهزة من NestJS.
- المهام الثقيلة (CPU) غير مناسبة في serverless → **مخفَّف بـ `apps/worker` منفصلة**.
- عميل خارجي يحتاج استخراجاً لاحقاً → **مخفَّف بعزل `core`**.

## خطة الاستخراج (عند الحاجة)

```
1. أنشئ apps/api بـ Fastify
2. استورد packages/core كما هو            ← بلا تعديل
3. أعد تنفيذ طبقة النقل فقط (~2–3 أيام)
4. حوّل apps/web لاستدعاء الـ API
5. انشر منفصلين
```
**صفر إعادة كتابة لمنطق الأعمال.** هذا ما يجعل القرار منخفض المخاطر.

## محفّزات إعادة النظر
تطبيق جوال · API للشركاء · تأثّر زمن الـ API بحمل العرض · حاجة لعمليات CPU طويلة في الطلب.
