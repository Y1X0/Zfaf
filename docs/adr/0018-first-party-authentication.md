# ADR-0018 — Authentication implemented directly on our own schema, not Auth.js

**الحالة:** 🟡 **Proposed — يحتاج موافقتك** · **التاريخ:** 2026-08-16
**يعدّل:** [02-technology-choices §4](../02-technology-choices.md) · [20-phase1-milestones D2.1](../20-phase1-milestones.md)
**يحافظ على:** [ADR-0006](0006-database-sessions-not-jwt.md) بالكامل

---

## ⚠️ لماذا هذا الـ ADR موجود

أثناء تنفيذ M2 ظهر **تعارض حقيقي** بين قرارين معتمدَين:

- **02-technology-choices §4** رشّح `Auth.js v5 + Prisma adapter`.
- **ADR-0006** فرض: *«يُخزَّن `sha256(token)` في `sessions` — لا الرمز الخام»*.

**هذان لا يجتمعان.** لم أنفّذ حلاً وسطاً صامتاً، بل أوقفت الجزء المتأثر ووثّقت المشكلة.

## السياق — التعارض بالتفصيل

محوّل Prisma الرسمي لـ Auth.js يفرض شكل جداول محدداً:

```prisma
model Session {
  sessionToken String   @unique   // ⚠️ الرمز الخام، بلا تجزئة
  userId       String
  expires      DateTime
}

model VerificationToken {
  identifier String
  token      String   @unique     // ⚠️ الرمز الخام أيضاً
  expires    DateTime
}
```

مقابل ما بنيناه في M1 تنفيذاً لـ ADR-0006:

```prisma
model Session {
  tokenHash Bytes     @unique     // ✅ sha256، لا الرمز
  expiresAt DateTime
  revokedAt DateTime?             // ✅ الإبطال الفوري
  ipHash    Bytes?
  userAgent String?
}
```

### ثلاث خسائر أمنية ملموسة لو تبنّينا المحوّل

| # | الخسارة | الأثر |
|---|---------|-------|
| 1 | **الرموز مخزَّنة خاماً** | تسريب قراءة فقط لقاعدة البيانات ⇒ المهاجم يملك **جلسات صالحة لكل المستخدمين فوراً**. هذا هو السبب المعلن لـ ADR-0006 |
| 2 | **لا `revokedAt`** | «تسجيل خروج من كل الأجهزة» و«إيقاف حساب مسيء فوراً» يصبحان مستحيلين. القدرة على الإبطال الفوري **هي المبرر الكامل** لاختيار جلسات DB بدل JWT |
| 3 | **رموز التفعيل/الاستعادة خاماً** | نفس مشكلة (1) على مسار استعادة كلمة المرور — أخطر مسار في النظام |

**النقطة الحاسمة:** لو اعتمدنا المحوّل، فإن ADR-0006 يصبح بلا معنى. اخترنا جلسات قاعدة بيانات
**تحديداً** للحصول على التجزئة والإبطال؛ محوّل يلغيهما يبطل القرار من أساسه.

## القرار المقترح

**تنفيذ المصادقة مباشرة على مخططنا، محافظاً على ADR-0006 حرفياً.**

```
Auth.js  →  ❌ لا يُستخدم
جلسات    →  رمز معتم 32 بايت من CSPRNG، يُخزَّن sha256 فقط
كلمات مرور →  argon2id بمعاملات OWASP
رموز مؤقتة →  32 بايت CSPRNG، مُجزّأة، استخدام واحد، منتهية الصلاحية
OAuth    →  ⏸ مؤجَّل حتى تُقرّ هذا الـ ADR (§ أدناه)
```

### ما نخسره بعدم استخدام Auth.js

بصراحة، وليس تقليلاً:

| ما يقدّمه Auth.js | هل نحتاجه؟ |
|-------------------|------------|
| إدارة الجلسات | ❌ لا — لدينا تنفيذنا، وهو **أقوى أمنياً** |
| تجزئة كلمات المرور | ❌ لا يقدّمها أصلاً (credentials provider يترك ذلك لك) |
| CSRF لمساراته | ⚠️ جزئياً — نبنيه في طبقة النقل على أي حال |
| **سباكة OAuth (Google)** | ✅ **نعم — هذه القيمة الحقيقية الوحيدة** |
| صفحات جاهزة | ❌ لا — واجهتنا عربية وRTL ومصمَّمة |

**الخلاصة الصادقة:** القيمة الفعلية الوحيدة هي OAuth. كل ما عداه إما لا نحتاجه أو
نحصل على أفضل منه.

### لذلك: Google OAuth مؤجَّل صراحةً

`D2.5` (Google OAuth) **لم يُنفَّذ في M2**، لأن اختيار طريقة تنفيذه يعتمد على هذا الـ ADR.
الخيارات عند الموافقة:

| الخيار | التقييم |
|--------|---------|
| **أ) `arctic`** — مكتبة OAuth صغيرة مركّزة | ⭐ موصى به: تعطي سباكة OAuth بلا فرض مخطط جلسات |
| ب) `openid-client` | ناضجة، أثقل، معيارية بالكامل |
| ج) Auth.js لمسار OAuth فقط + جلساتنا | يتطلب محوّلاً مخصصاً — تعقيد بلا مقابل |
| د) تنفيذ يدوي | يتطلب تحقق JWKS يدوياً — خطر غير مبرَّر |

جدول `oauth_accounts` **موجود في المخطط**، فإضافة المزوّد لاحقاً لا تتطلب migration.

## البدائل المرفوضة

| البديل | لماذا رُفض |
|--------|------------|
| تبنّي مخطط Auth.js كما هو | يلغي ADR-0006 — خسارة أمنية غير مقبولة |
| كتابة محوّل Prisma مخصص لـ Auth.js | كل تعقيد Auth.js + كل عمل التنفيذ اليدوي، مقابل صفر مكسب |
| تخزين الرمز خاماً «مؤقتاً» | ❌ لا يوجد «مؤقت» في الأمن |
| Clerk / Supabase Auth | مرفوضة أصلاً في 02 §4 (تكلفة، قفل مزوّد، بيانات خارجاً) |

## العواقب

### إيجابية
- ADR-0006 محفوظ حرفياً: رموز مُجزّأة + إبطال فوري + «أجهزتي».
- تبعيات أقل على مسار المصادقة — سطح هجوم وسلسلة توريد أصغر.
- تحكم كامل في الرسائل والتوقيت (مقاومة تعداد الحسابات تحتاج ضبطاً دقيقاً).
- منطق المصادقة في `packages/core` — قابل للاختبار بلا HTTP، متسق مع ADR-0002.

### سلبية
- **نتحمل مسؤولية كود أمني حسّاس بأنفسنا.** مخفَّف بـ: اتباع OWASP حرفياً،
  تغطية اختبارية كثيفة، ومراجعة اختراق خارجية قبل الإطلاق (مخطط لها أصلاً).
- OAuth مؤجَّل ⇒ تسجيل الدخول بالبريد فقط حتى يُقرّ هذا الـ ADR.
- لا نستفيد من تدقيق مجتمعي لكود Auth.js.

## ما نُفِّذ فعلاً في M2 تحت هذا الافتراض

كل ما لا يعتمد على القرار المعلّق:

```
✅ تسجيل · دخول · خروج · خروج من كل الأجهزة
✅ argon2id + سياسة كلمات المرور
✅ جلسات معتمة مُجزّأة + تمديد انزلاقي + حد أقصى مطلق
✅ تفعيل البريد (رمز مُجزّأ، استخدام واحد)
✅ استعادة كلمة المرور (15 دقيقة، استخدام واحد، إبطال كل الجلسات)
✅ حدود المعدل ومقاومة التعداد
✅ العضوية وسياق المستأجر
⏸ Google OAuth — معلّق على موافقتك
```

## طلب القرار

> **هل توافق على تنفيذ المصادقة على مخططنا مع الحفاظ على ADR-0006؟**
> وإن نعم، **أي خيار لـ OAuth؟** (أ) `arctic` — توصيتي · (ب) `openid-client` · (ج) تأجيل OAuth إلى ما بعد MVP

عند الموافقة: تُحوَّل حالة هذا الـ ADR إلى `Accepted`، ويُحدَّث
[02-technology-choices §4](../02-technology-choices.md)، ويُنفَّذ `D2.5`.
