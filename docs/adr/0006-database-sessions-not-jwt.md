# ADR-0006 — جلسات قاعدة بيانات في httpOnly cookies بدل JWT

**الحالة:** ✅ Accepted · **اقتُرح:** 2026-08-16 · **اعتُمد:** 2026-08-16

## السياق

نحتاج مصادقة لعملاء (يبنون دعوات) وموظفين (لهم صلاحيات واسعة).
المنصة **قابلة لإساءة الاستخدام** (أي شخص ينشر محتوى عاماً)، لذلك القدرة على إيقاف
حساب أو جلسة **فوراً** ليست ميزة إضافية بل متطلب تشغيلي.

## القرار

**رمز جلسة معتم (opaque) في httpOnly cookie، مع سجل الجلسة في PostgreSQL.**

```
__Host-zfaf_session=<base64url(32 random bytes)>
HttpOnly; Secure; SameSite=Lax; Path=/; Max-Age=2592000
```

- يُخزَّن **`sha256(token)`** في `sessions` — لا الرمز الخام.
- انتهاء 30 يوماً بتمديد انزلاقي، وحد أقصى مطلق 90 يوماً.
- جلسات الموظفين: **4 ساعات فقط**.
- JWT يُستخدم **فقط** لأغراض قصيرة العمر وموقّعة: روابط الوسائط، تفعيل البريد، رموز الضيوف.

## المقارنة

| المتطلب | JWT | جلسات DB |
|---------|:---:|:--------:|
| تسجيل خروج من كل الأجهزة | ❌ يحتاج قائمة إبطال (= DB على أي حال) | ✅ `UPDATE` واحد |
| إيقاف حساب مسيء فوراً | ❌ الرمز صالح حتى انتهائه | ✅ فوري |
| تغيير الدور يسري فوراً | ❌ | ✅ |
| «أجهزتي النشطة» | ❌ | ✅ |
| حجم الكوكي | كبير | 32 بايت |
| بلا حالة | ✅ | ❌ |
| زمن التحقق | أسرع نظرياً | بحث بمفتاح (~1ms) |

**الحجّة المضادة الشائعة:** «JWT أسرع لأنه بلا استعلام DB».
**لماذا لا تنطبق علينا:** الطلب المصادق عليه سيلمس قاعدة البيانات على أي حال
(لجلب الدعوة أو الردود). استعلام إضافي بمفتاح رئيسي مُخزَّن مؤقتاً = تكلفة مهملة.

**الحجّة الأقوى للجلسات:** JWT مع قائمة إبطال **هو جلسات DB مع خطوات إضافية** —
تفقد ميزة انعدام الحالة وتحتفظ بتعقيدها.

## البدائل المرفوضة

| البديل | لماذا |
|--------|-------|
| JWT قصير + refresh token | تعقيد تدوير الرموز، والـ refresh نفسه في DB ⇒ نفس التكلفة بلا فائدة |
| Clerk / Auth0 | تكلفة متصاعدة، قفل مزوّد، بيانات مستخدمينا خارجاً، تعريب محدود |
| جلسات في Redis | أسرع لكن فقدان Redis = خروج الجميع. الجلسات بيانات دائمة تنتمي لـ DB |

## العواقب

### إيجابية
تحكم أمني كامل · إبطال فوري · «أجهزتي» · كوكي صغير · لا مفاتيح توقيع تُدار وتُدوَّر.

### سلبية
- استعلام لكل طلب مصادق → **مخفَّف بتخزين مؤقت قصير (30 ثانية) في Redis مع إبطال عند الخروج**.
- الجلسات حالة في DB → تنظيف دوري للمنتهية.
- التوسع الأفقي يتطلب DB مشتركة → **هي مشتركة أصلاً في تصميمنا**.

## الأمان

- بادئة `__Host-` تفرض `Secure` و `Path=/` وتمنع الضبط من نطاق فرعي.
- تخزين الـ hash يعني أن تسريب قاعدة البيانات **لا يعطي المهاجم جلسات صالحة**.
- تدوير الرمز عند تصعيد الصلاحية.
- إبطال كل الجلسات عند: تغيير كلمة المرور، إعادة التعيين، إيقاف الحساب، طلب الحذف.
- تسجيل `ip_hash` و `user_agent` لعرضها للمستخدم وكشف الاختطاف.
