# ADR-0003 — PostgreSQL + Prisma ORM

**الحالة:** Proposed · **التاريخ:** 2026-08-16 · **القرار المرتبط:** #2

## السياق

نحتاج تخزيناً يدعم:
- علاقات حقيقية ومعاملات ACID (النشر، الدفع، عدّادات RSVP).
- مستندات مرنة (`draft_document`, `published_document`, `manifest`) → JSONB.
- قيوداً فريدة جزئية (الـ slug فريد بين غير المحذوفة فقط).
- بحثاً نصياً بالعربية.
- تقسيماً للجداول عالية الحجم (analytics, audit).

## القرار

**PostgreSQL 16** كقاعدة البيانات · **Prisma 6** كـ ORM · **Neon** كمزوّد في Phase 1–2.

## لماذا PostgreSQL

| البديل | لماذا لا |
|--------|----------|
| MySQL | دعم JSONB أضعف بوضوح، ونحن نعتمد عليه مركزياً |
| MongoDB | نحتاج معاملات علائقية حقيقية؛ الاتساق ليس رفاهية في الدفع والمقاعد |
| SQLite/Turso | ممتاز للقراءة الموزّعة، لكن كتابة متزامنة + migrations متعددة المستأجرين خطر |

**ميزات نستخدمها فعلاً:** JSONB + فهارس GIN · فهارس فريدة جزئية · RLS (دفاع في العمق)
· تقسيم بالمدى · `citext` · `pg_trgm` (بحث الأسماء العربية) · PITR.

## لماذا Prisma (وليس Drizzle)

كان هذا القرار الأقرب للتعادل. المقارنة الصادقة:

| المعيار | Prisma | Drizzle |
|---------|:------:|:-------:|
| نضج الـ migrations | 🟢 ممتاز | 🟡 جيد، أحدث |
| الـ schema كوثيقة حية | 🟢 يُقرأ كـ ERD | 🟡 TypeScript |
| SQL معقّد | 🟡 `$queryRaw` | 🟢 SQL-first |
| الحجم / cold start | 🟡 أثقل | 🟢 أخف |
| النظام البيئي والتوظيف | 🟢 أوسع | 🟡 ينمو |

**الحاسم:** أخطر ما في هذا المشروع ليس أداء الـ ORM — بل **سلامة الـ migrations** على بيانات
حقيقية لأعراس حقيقية، و**سرعة الفريق**. Prisma يتفوق في الاثنين.

**سياق مخفِّف:** استعلاماتنا في المسار الحرج بسيطة جداً (`findFirst` على snapshot واحد).
كل التعقيد في التحليلات، وهي ستُكتب SQL خاماً مقصوداً في `packages/db/analytics/` مع اختبارات تكامل.

## العواقب

### إيجابية
schema واحد يخدم كوثيقة ERD · أنواع مولّدة · migrations موثوقة · مجتمع واسع.

### سلبية
- حجم أكبر و cold start أبطأ في serverless → **مخفَّف بـ connection pooling (Neon driver / PgBouncer)**.
- SQL معقّد يفقد أمان النوع → **محصور في مجلد واحد مع اختبارات**.
- طبقة تجريد قد تخفي استعلامات سيئة → **تسجيل الاستعلامات البطيئة + مراجعة `EXPLAIN` للحرجة**.

## محفّزات إعادة النظر

- Cold start يهدد ميزانية الأداء.
- نسبة `$queryRaw` > 30% من الاستعلامات.
- الحاجة لتشغيل على Edge runtime.

**قابلية الانعكاس:** الوصول للبيانات معزول خلف واجهات `Repository` في `packages/db`.
تبديل الـ ORM = إعادة كتابة تلك الطبقة فقط، بلا مساس بمنطق الأعمال.
