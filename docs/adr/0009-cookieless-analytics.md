# ADR-0009 — تحليلات بلا Cookies وبلا تخزين IP

**الحالة:** Proposed · **التاريخ:** 2026-08-16

## السياق

صاحب الدعوة يحتاج أرقاماً حقيقية: كم شاهد؟ كم زائراً فريداً؟ من أي جهاز؟

لكن الزوار **ضيوف حفل زفاف** — أطراف ثالثة لم يوافقوا على شيء، ولا يعرفون بوجودنا،
وجاؤوا لمعرفة موعد ومكان. تتبعهم بالمعنى الإعلاني **غير أخلاقي وغير مبرر تجارياً**.

المتطلب صريح: *«لا تجمع بيانات حساسة أو غير ضرورية»* و *«Country/region بشكل privacy-friendly»*.

## القرار

**تحليلات مجهّلة، بلا كوكيز، وبلا تخزين عناوين IP إطلاقاً.**

```
visitor_hash = SHA256( daily_salt ‖ client_ip ‖ user_agent ‖ invitation_id )
```

الخصائص الحاسمة:
- `daily_salt` **يُولَّد عشوائياً كل 24 ساعة ولا يُخزَّن بشكل دائم**.
- بعد انقضاء اليوم، لا يمكن **لأحد — بمن فينا نحن** — عكس الـ hash أو ربط زيارات عبر الأيام.
- `invitation_id` داخل الـ hash يمنع تتبع نفس الزائر عبر دعوات مختلفة.
- لا كوكيز، لا `localStorage`، لا بصمة جهاز، لا معرّف ثابت.

### ما نخزّنه فعلاً

| الحقل | المصدر | الدقة |
|-------|--------|-------|
| `invitation_id` | السياق | دقيق |
| `type` | الحدث | `view`, `rsvp_submit`, `share`, `maps_click`... |
| `visitor_hash` | محسوب | فريد **ضمن اليوم فقط** |
| `country` | ترويسة CDN | **الدولة فقط** — لا مدينة ولا إحداثيات |
| `device_class` | User-Agent | `mobile` / `tablet` / `desktop` فقط |
| `referrer_class` | Referer | `whatsapp` / `direct` / `social` / `search` / `other` |
| `occurred_at` | الخادم | الطابع الزمني |

### ما لا نخزّنه

❌ IP خام · ❌ كوكيز · ❌ معرّف ثابت · ❌ User-Agent كاملاً · ❌ المدينة أو الإحداثيات
❌ مسار الزيارة عبر مواقع · ❌ أي معرّف قابل للربط بشخص

## البدائل المرفوضة

| البديل | لماذا |
|--------|-------|
| Google Analytics | تتبع واسع، مشاركة بيانات، cookie banner إلزامي، سكربت ثقيل، ومخالف لروح المتطلبات |
| Plausible/Fathom مستضاف | ممتازان من ناحية الخصوصية، لكن نحتاج بيانات لكل دعوة مربوطة ببياناتنا — تكامل معقّد بلا فائدة |
| كوكيز أولية للزوار الفريدين | تحتاج cookie banner ⇒ **يخرّب تجربة فتح الدعوة** ويقلل التحويل |
| بصمة الجهاز (fingerprinting) | ❌ أسوأ من الكوكيز أخلاقياً، وبلا موافقة |
| لا تحليلات إطلاقاً | صاحب الدعوة يحتاج الأرقام فعلاً — طلب مشروع |

## العواقب

### إيجابية
- **لا حاجة لـ cookie banner** — ميزة تجربة حقيقية على الصفحة العامة، لا مجرد امتثال.
- سطح مخاطر خصوصية شبه معدوم — تسريب البيانات لا يكشف شيئاً عن أي شخص.
- سكربت خفيف جداً (< 1KB) بدل 40KB+ لـ GA.
- امتثال طبيعي لأي إطار خصوصية بلا عمل إضافي.
- **يبني ثقة** — نقطة بيع تسويقية حقيقية في سوق حساس للخصوصية.

### سلبية
- **لا يمكن تتبع الزائر عبر الأيام** ⇒ لا «زوار عائدون» عبر أسابيع.
  → **مقبول تماماً**: الدعوة تُشاهَد عادة في نافذة قصيرة.
- تقدير الزوار الفريدين تقريبي (مشاركة IP في شبكة واحدة قد تدمج زائرين).
  → مقبول: الاتجاه أهم من الرقم المطلق.
- لا تحليل قمع تسويقي تفصيلي.
  → مقبول: نقيس التحويل بمقاييس الخادم (منشور/مشاهدة/رد) لا بتتبع الأفراد.

## التنفيذ

```typescript
// إرسال من العميل — لا يحمل أي معرّف
navigator.sendBeacon('/api/public/analytics/event',
  JSON.stringify({ invitationId, type: 'view' }));

// الخادم يستخرج كل شيء من الترويسات
const salt = await getDailySalt();                    // Redis، TTL 24 ساعة، لا يُحفظ
const hash = sha256(salt + ip + userAgent + invitationId);
```

- إرسال fire-and-forget، يرد `204` دائماً — **لا يفشل أبداً على العميل**.
- `analytics_events` مقسّم شهرياً، احتفاظ 90 يوماً (`DROP PARTITION`).
- تجميع كل ساعة إلى `analytics_daily` (يُحتفَظ به دائماً، مجهّل بالكامل).
- عدّاد المشاهدات يُجمَّع في Redis ويُغسَل كل 60 ثانية — لا كتابة DB مع كل مشاهدة.
