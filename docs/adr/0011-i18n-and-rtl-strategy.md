# ADR-0011 — next-intl + CSS Logical Properties لدعم العربية و RTL

**الحالة:** ✅ Accepted · **اقتُرح:** 2026-08-16 · **اعتُمد:** 2026-08-16

## السياق

المنتج **عربي أولاً**، والإنجليزية ثانية. RTL ليس ميزة إضافية — إنه الوضع الافتراضي.
المتطلب صريح: *«اللغة لا يجب أن تكون Hard-coded»* و *«لا تهمل RTL»*.

الواقع المؤلم: معظم المشاريع تضيف RTL لاحقاً، فتنتهي بمئات الإصلاحات المتناثرة
(`[dir="rtl"] .foo { margin-right: ... }`) التي تتكسر مع كل تغيير تصميم.

## القرار

### 1. المكتبة: `next-intl`
تكامل أصلي مع App Router و RSC · توجيه حسب اللغة · تنسيق ICU للتواريخ والأرقام والجمع.

### 2. التوجيه
```
/ar/...   ← الافتراضي، بلا إعادة توجيه من /
/en/...
/i/{slug} ← ⚠️ خارج مقطع [locale] عمداً
```

**لماذا `/i/{slug}` خارج `[locale]`؟**
لغة الدعوة خاصية **للدعوة** لا للزائر. دعوة عربية تُعرض عربية لضيف في لندن.
وضعها تحت `[locale]` كان سينتج رابطين لنفس المحتوى (`/ar/i/x` و `/en/i/x`) —
خطأ في SEO وفي المشاركة (أي رابط يُرسَل؟).

### 3. RTL عبر CSS Logical Properties — **حصراً**

```css
/* ❌ ممنوع في أي مكوّن مشترك */
margin-left: 1rem;  padding-right: 2rem;  text-align: left;  border-left: 1px;

/* ✅ مطلوب */
margin-inline-start: 1rem;  padding-inline-end: 2rem;
text-align: start;  border-inline-start: 1px;
```

Tailwind v4: `ms-4` `me-4` `ps-2` `pe-2` `text-start` `border-s` `rounded-s-lg`.

**الفرض الآلي:** قاعدة ESLint مخصصة تمنع الخصائص الفيزيائية في `packages/ui`
و `packages/invitation-renderer` — **تفشل CI**.

> هذه القاعدة هي جوهر القرار. بدونها ستتسلل `margin-left` تدريجياً ويتحول RTL
> إلى ديون تقنية دائمة. الفرض بالأداة لا بالانضباط.

## البدائل المرفوضة

| البديل | لماذا |
|--------|-------|
| `next-i18next` | مبني لـ Pages Router، تكامل RSC ضعيف |
| `Lingui` | ممتاز لكن إعداد أثقل وخط بناء إضافي |
| `react-intl` وحده | بلا تكامل مع التوجيه |
| RTL عبر `postcss-rtlcss` (قلب آلي) | يقلب أشياء **يجب ألا تُقلب** (أيقونات، شعارات، اتجاه التمرير في بعض السياقات)، ويُخفي المشكلة بدل حلها |
| RTL بأنماط تجاوز `[dir="rtl"]` | يتضاعف بلا نهاية ويتكسر مع كل تغيير |

## قواعد إضافية

1. **الأيقونات الاتجاهية تنعكس، وغيرها لا.**
   ```css
   [dir="rtl"] .icon-directional { transform: scaleX(-1); }
   ```
   الأسهم والرجوع → تنعكس. تشغيل الصوت، ساعة، قلب، بحث → **لا تنعكس**.
   قائمة صريحة في `packages/ui`.

2. **كل الأرقام والتواريخ عبر `Intl`**، لا تنسيق يدوي إطلاقاً.

3. **المحتوى المختلط** (اسم إنجليزي داخل نص عربي) يُلَفّ بـ `<bdi>` لعزل الاتجاه.

4. **الطباعة العربية:**
   ```css
   line-height: 1.9;        /* أعلى من اللاتينية — التشكيل والنقاط تحتاج مساحة */
   letter-spacing: 0;       /* ⚠️ أي قيمة أخرى تكسر اتصال الحروف — ممنوع */
   font-feature-settings: "liga" 1, "calt" 1;
   ```
   الحد الأدنى للقراءة على الجوال: **16px**.

5. **الاختبار:** كل لقطة بصرية تُلتقط بلغتين. اختلاف غير متوقع = فشل CI.

6. **اختبار بنصوص عربية حقيقية طويلة** — لا Lorem Ipsum ولا كلمة واحدة.
   الأسماء العربية الحقيقية أطول مما يتوقعه المصمم، وتكشف مشاكل التفاف النص.

## العواقب

### إيجابية
- RTL صحيح **بالبناء** لا بالترقيع — يعمل تلقائياً لأي مكوّن جديد.
- إضافة لغة ثالثة (فرنسية/أردية/تركية) شبه مجانية.
- الخصائص المنطقية مدعومة أصلاً في كل المتصفحات المستهدفة.
- تحسين واحد يفيد الاتجاهين معاً.

### سلبية
- الخصائص المنطقية أقل ألفة لبعض المطورين — منحنى تعلّم قصير.
- بعض مكتبات الطرف الثالث لا تدعم RTL → **معيار اختيار صريح للمكتبات**.
- ملفات ترجمة تحتاج صيانة → مخفَّف بفحص المفاتيح الناقصة في CI.
