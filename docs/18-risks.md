## 2. المخاطر التقنية

### T1 — محرك القوالب لا يفي بوعده 🔴

| | |
|---|---|
| **الوصف** | يتبيّن أن كل قالب جديد يحتاج كوداً — فينهار الوعد الأساسي وتصبح المنصة ورشة يدوية. |
| **الاحتمال** | **متوسط** — هذا أصعب جزء تقني في المشروع |
| **الأثر** | **حرج** |
| **التخفيف** | ① بناء **ثلاثة قوالب مختلفة جذرياً** في MVP — ليس ثلاث تنويعات لنفس التصميم<br>② القالب الثالث هو **اختبار الصحة**: إن احتاج تعديل Renderer، نُصلح التصميم فوراً لا لاحقاً<br>③ فصل صارم: type ثابت / variant قابل للنمو<br>④ قياس مستمر: نسبة القوالب التي احتاجت كوداً |
| **المؤشر** | القالب الرابع أو الخامس احتاج تعديل `InvitationRenderer` |
| **الخطة البديلة** | قبول أن variant واحد جديد لكل قالب أمر طبيعي (المهم أنه **قدرة عامة** لا نسخة) |

### T2 — أداء الصفحة العامة يتدهور تدريجياً

| | |
|---|---|
| **الاحتمال** | **عالٍ** — هذا يحدث في كل مشروع بلا استثناء |
| **الأثر** | عالٍ |
| **التخفيف** | ميزانيات أداء **مفروضة في CI** تفشل الـ build · Server Components افتراضياً · لا مكتبات animation على الصفحة العامة · RUM من مستخدمين حقيقيين · مراجعة أداء لكل PR يضيف JS |

### T3 — الصوت لا يعمل في متصفح WhatsApp الداخلي

| | |
|---|---|
| **الاحتمال** | متوسط |
| **الأثر** | متوسط |

### T4 — التوقيت والمناطق الزمنية

| | |
|---|---|
| **الوصف** | عد تنازلي خاطئ، أو تاريخ يظهر مختلفاً — يدمّر الثقة فوراً. |

### T5 — الطباعة العربية والـ RTL

## 3. المخاطر القانونية والامتثال

|---|---|

| | |
|---|---|

| | |
|---|---|

## 4. المخاطر التشغيلية

### O1 — انقطاع ليلة عرس 🔴

| | |
|---|---|
| **الوصف** | الدعوة لا تُفتح في الليلة التي تهم. **لا يمكن تعويض هذا الضرر.** |

| **الأثر** | **حرج** للعميل، عالٍ للسمعة |
| **التخفيف** | ① `stale-while-revalidate=86400` → **الدعوة تعمل 24 ساعة حتى لو سقط كل شيء**<br>② SLO 99.9% للصفحة العامة<br>③ تجميد النشر في أوقات الذروة (ليالي الخميس والجمعة)<br>④ تنبيهات P0 مع استجابة فورية<br>⑤ صفحة حالة مستضافة خارجياً |

### O2 — ذروة مفاجئة (دعوة تنتشر)

| | |
|---|---|
| **الاحتمال** | متوسط |
| **الأثر** | متوسط |
| **التخفيف** | CDN يمتص الحمل · صور محسّنة (وإلا انفجر عرض النطاق) · حدود معدل · تنبيهات تكلفة · اختبار حمل قبل الإطلاق |

### O3 — الاعتماد على فرد واحد (Bus factor)

|---|---|

### O4 — البريد لا يصل

| | |
|---|---|
| **الوصف** | بريد التفعيل في مجلد الرسائل غير المرغوبة ⇒ المستخدم لا يستطيع النشر ⇒ يغادر. |

## 6. الإدارة

- **مراجعة أسبوعية** لأعلى 6 مخاطر أثناء التطوير النشط.
- **مراجعة شهرية** للسجل كاملاً.
- كل خطر له **مالك** ومؤشر إنذار مبكر واضح.
- المخاطر الجديدة تُسجَّل فور اكتشافها — لا تنتظر المراجعة.
- **مراجعة بلا لوم أشخاص** بعد كل حادث، والنتائج تُضاف كمخاطر أو ضوابط.
