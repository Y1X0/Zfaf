## 1. الأصول التي نحميها

مرتّبة حسب أثر الاختراق:

| # | الأصل | الحساسية | لماذا |
|---|-------|:--------:|-------|
| A1 | **بيانات الضيوف** (أسماء، هواتف) | 🔴 حرجة | أطراف ثالثة لم توافق على شيء. تسريبها = ضرر لأناس لا نعرفهم |
| A2 | **بيانات حساب المستخدم** (بريد، كلمة مرور) | 🔴 حرجة | إعادة استخدام كلمات المرور = اختراق حسابات أخرى |
| A3 | **صور العروسين والعائلة** | 🔴 حرجة | حساسية ثقافية عالية في المنطقة. صورة عروس مسربة = ضرر اجتماعي حقيقي |
| A4 | **موقع وتوقيت الحفل** | 🟠 عالية | معلومة تمكينية: منزل فارغ في وقت معلوم |
| A5 | **سجلات الدفع** | 🟠 عالية | مالية |
| A6 | **جلسات المستخدمين** | 🟠 عالية | الاستيلاء على الحساب |
| A7 | **سلامة الدعوة المنشورة** | 🟠 عالية | تشويه دعوة = ضرر سمعة فوري وعلني |
| A8 | **حسابات الموظفين** | 🔴 حرجة | وصول واسع |
| A9 | توفر المنصة | 🟡 متوسطة | عرس واحد لا يتأجل — لكن الضرر محدود زمنياً |

> **ملاحظة سياقية مهمة:** A3 و A4 أخطر في سياقنا الثقافي مما تبدو في تحليل غربي معياري.
> صور نساء العائلة مسألة خصوصية بالغة الحساسية في المجتمعات المستهدفة. هذا يبرر قرارات مثل
> `noindex` افتراضياً، وتجريد EXIF، ومنع الموظفين من رؤية بيانات الضيوف.

## 2. سطح الهجوم

```
🌐 عام بلا مصادقة (الأخطر)
   ├── GET  /i/{slug}                          ← تعداد، حجب خدمة
   ├── POST /api/public/*/rsvp                 ← بريد مزعج، تلوث بيانات، حقن
   ├── POST /api/public/analytics/event        ← تلوث بيانات
   ├── POST /api/public/reports                ← إساءة استخدام البلاغات
   ├── POST /auth/{register,login,forgot}      ← تخمين، تعداد حسابات
   └── POST /api/webhooks/*                    ← أحداث مزوّرة

🔐 مصادق عليه
   ├── /api/v1/invitations/*                   ← IDOR، تجاوز التفويض
   ├── /api/v1/media/upload-url                ← رفع خبيث، استنزاف تخزين
   ├── PATCH .../document                      ← حقن، تسمم بيانات
   └── /api/v1/checkout/*                      ← تلاعب بالأسعار

👤 محتوى المستخدم (يظهر لأطراف ثالثة)
   ├── نصوص الدعوة                             ← XSS
   ├── الصور                                   ← ملفات خبيثة، تسريب EXIF
   ├── الـ slug                                ← انتحال، إساءة
   └── mapsUrl                                 ← إعادة توجيه مفتوحة، تصيّد

🛡️ إداري
   └── /admin/*                                ← تصعيد صلاحيات، إساءة داخلية
```

## 3. تحليل STRIDE

### S — انتحال الهوية (Spoofing)

| التهديد | الأثر | الضوابط |
|---------|-------|---------|
| تخمين كلمات المرور | استيلاء على حساب | حد معدل متعدد الطبقات، قفل تصاعدي، Turnstile، argon2id، فحص كلمات المرور المسربة |
| اختطاف الجلسة | استيلاء | كوكي `__Host-` + HttpOnly + Secure + SameSite، HSTS، رموز مُجزّأة في DB |
| webhook مزوّر | حالة دفع كاذبة | تحقق توقيع HMAC + نافذة زمنية + معرّف حدث فريد |
| انتحال عرس شخص آخر | ضرر سمعة | كلمات محجوزة، آلية بلاغ، إيقاف سريع |
| تصيّد يقلّد Zfaf | سرقة بيانات | DMARC، مراقبة تسجيل نطاقات مشابهة، تثقيف المستخدمين |
| استيلاء عبر OAuth | استيلاء | الربط بالبريد **فقط** إن كان `email_verified` من المزوّد |

### T — التلاعب (Tampering)

| التهديد | الأثر | الضوابط |
|---------|-------|---------|
| **IDOR** — تعديل دعوة غيرك | تشويه، تسريب | `can()` مركزية، مستودعات تفرض النطاق، **404 لا 403**، مصفوفة اختبار آلية |
| تلاعب بالسعر | خسارة مالية | السعر من DB، العميل يرسل `planId` فقط |
| حقن SQL | اختراق كامل | استعلامات مُعدّة (Prisma)، SQL خام مُعامَل حصراً، **قاعدة CI تمنع تركيب السلاسل** |
| حقن NoSQL/JSON | تجاوز منطق | Zod صارم مع `.strict()`، رفض المفاتيح غير المعروفة |
| **تلاعب بـ JSON Patch** | تعديل حقول محظورة | ✅ **قائمة بيضاء لمسارات الـ patch** — لا يستطيع الـ patch لمس `id`, `ownerId`, `status`, `publishedVersionId` |
| تلوث النموذج الأولي | RCE محتمل | رفض مفاتيح `__proto__`, `constructor`, `prototype` في كل JSON وارد |
| اجتياز المسار في الرفع | كتابة عشوائية | مفاتيح مولّدة من الخادم، اسم الملف الأصلي **لا يُستخدم في المسار إطلاقاً** |
| تجاوز حد المقاعد في RSVP | بيانات خاطئة | تحقق server-side مقابل `max_party_size` |

> ⚠️ **قائمة مسارات الـ Patch البيضاء بند أمني حرج.** بدونها، `PATCH /document` بمسار
> `/status` أو `/ownerId` يصبح تصعيد صلاحيات مباشراً. المسموح فقط:
> `/theme/**`, `/sections/**`, `/content/**`. أي مسار آخر ⇒ رفض فوري وتسجيل كمحاولة.

### R — الإنكار (Repudiation)

| التهديد | الضوابط |
|---------|---------|
| إنكار إجراء إداري | `audit_logs` غير قابل للتعديل، احتفاظ سنتان |
| نزاع على دفعة | سجلات دفع كاملة + سجل webhooks + إيصالات |
| «لم أنشر هذا» | سجل النشر مع الفاعل، الوقت، IP hash، request ID |

### I — كشف المعلومات (Information Disclosure)

| التهديد | الأثر | الضوابط |
|---------|-------|---------|
| **XSS مخزَّن عبر محتوى الدعوة** | سرقة جلسات الضيوف | React يهرّب افتراضياً، **`dangerouslySetInnerHTML` ممنوع بقاعدة ESLint**، CSP صارم |
| XSS عبر رفع SVG | تنفيذ سكربت | **SVG مرفوض قطعياً**، تحقق magic bytes، CSP على نطاق الوسائط |
| **تسريب GPS عبر EXIF** | كشف عنوان المنزل | **تجريد كامل للميتاداتا في الـ worker** — غير قابل للتعطيل |
| تعداد الـ slugs | حصاد دعوات | لا فهرس عام، حد معدل، الـ slugs غير قابلة للتعداد (لا تسلسل) |
| تعداد الحسابات | قائمة أهداف | ردود موحّدة، توقيت ثابت في `login` و `forgot-password` |
| فهرسة الدعوات في Google | تسريب خصوصية | **`noindex` افتراضياً** — تفعيل صريح فقط |
| ⚠️ **سوء فهم «noindex = سرّي»** | أمان وهمي ⇒ مشاركة غير محسوبة | **نصوص صدق إلزامية في الواجهة** — `UNLISTED` لا يعني خاص. [ADR-0017](adr/0017-invitation-visibility-model.md) |
| تسريب في رسائل الأخطاء | معلومات داخلية | أخطاء عامة للعميل، التفاصيل في السجلات فقط |
| تسريب في الـ Referer | تسريب رمز الضيف | `Referrer-Policy: no-referrer` على صفحة الدعوة |
| موظف يتصفح بيانات الضيوف | تسريب داخلي | **الموظفون لا يرون بيانات الضيوف** (§ [09](09-auth-and-rbac.md#33-خصوصية-بيانات-الضيوف-من-الموظفين)) |
| تسريب عبر التحليلات | تتبع | لا IP مخزَّن، لا كوكيز، ملح يومي غير محفوظ |

### D — حجب الخدمة (Denial of Service)

| التهديد | الضوابط |
|---------|---------|
| فيضان طلبات على `/i/{slug}` | Cloudflare CDN + WAF + حماية من الروبوتات؛ الصفحة مخزّنة أصلاً |
| بريد مزعج في RSVP | حد معدل + honeypot + Turnstile + كشف تكرار |
| استنزاف التخزين | حصص لكل باقة، حدود حجم، حد معدل الرفع |
| قنابل الضغط (Zip/Image bombs) | حدود الأبعاد + `limitInputPixels` + مهلة معالجة |
| مستند دعوة ضخم | ≤ 256KB، ≤ 30 قسماً، ≤ 60 صورة |
| فيضان تسجيل حسابات | حد معدل + تفعيل بريد مطلوب للنشر |
| استعلامات ثقيلة | مهلة استعلام، ترقيم إجباري، فهارس مدروسة |
| فيضان webhooks | حد معدل + المعالجة في طابور خارج الطلب |

### E — تصعيد الامتيازات (Elevation of Privilege)

| التهديد | الضوابط |
|---------|---------|
| مستخدم → أدمن | الدور من DB في كل طلب، لا يُقرأ من عميل، فحص server-side دائماً |
| viewer → editor | `can()` مركزية + اختبارات مصفوفة كاملة |
| تجاوز عزل المستأجرين | فرض في المستودع + RLS (Ph2) + اختبارات IDOR آلية |
| مسار patch محظور | قائمة بيضاء صارمة |
| تصعيد عبر تبعية | Dependabot + `npm audit` + تثبيت الإصدارات + مراجعة التبعيات الجديدة |
| كود خبيث في manifest (Ph3) | **الـ manifest بيانات لا كود** — لا تنفيذ ممكن أصلاً |

## 4. سياسة أمان المحتوى (CSP)

### الصفحة العامة `/i/{slug}` — الأصرم

```
Content-Security-Policy:
  default-src 'none';
  script-src 'self' 'nonce-{random}';
  style-src 'self' 'nonce-{random}';
  img-src 'self' https://cdn.zfaf.app data:;
  media-src 'self' https://cdn.zfaf.app;
  font-src 'self';
  connect-src 'self';
  form-action 'self';
  frame-ancestors 'none';
  base-uri 'none';
  object-src 'none';
  upgrade-insecure-requests;
```

**نقاط مهمة:**
- ❌ **لا `unsafe-inline` ولا `unsafe-eval`.** الـ nonce يغطي الثيم المحقون inline.
- ❌ لا نطاقات خارجية إطلاقاً — لا خطوط Google، لا خرائط مضمّنة، لا تحليلات طرف ثالث.
  (هذا أحد أسباب قرار استضافة الخطوط ذاتياً واستخدام صورة خريطة ثابتة.)
- `frame-ancestors 'none'` — لا يمكن تضمين الدعوة في إطار (ضد clickjacking والتصيّد).
- `object-src 'none'` + `base-uri 'none'` — إغلاق نواقل قديمة معروفة.

### نطاق الوسائط
```
Content-Security-Policy: default-src 'none'; sandbox
X-Content-Type-Options: nosniff
```

### باقي الترويسات
```
Strict-Transport-Security: max-age=63072000; includeSubDomains; preload
X-Content-Type-Options: nosniff
X-Frame-Options: DENY
Referrer-Policy: no-referrer                    (على صفحة الدعوة)
Permissions-Policy: geolocation=(), microphone=(), camera=(), payment=(), usb=()
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Resource-Policy: same-site
```

## 5. منع الإساءة

منصة يستطيع أي شخص النشر عليها = هدف حتمي للإساءة.

### نواقل الإساءة المتوقعة

| الناقل | التخفيف |
|--------|---------|
| استضافة تصيّد على شكل «دعوة» | فحص عند النشر (أنماط، روابط)، بلاغات، إيقاف سريع، `noindex` يقلّل الجاذبية |
| نشر محتوى غير لائق | بلاغات، مراجعة، إيقاف، حظر |
| بريد مزعج عبر RSVP | حد معدل، Turnstile، honeypot |
| انتحال عرس شخص حقيقي | آلية بلاغ + إيقاف + التحقق عند النزاع |
| حصاد بيانات الضيوف | لا واجهة عامة لقراءة الردود إطلاقاً |
| إنشاء حسابات آلي | حد معدل + تفعيل بريد للنشر + كشف بريد مؤقت |
| استغلال للتخزين المجاني | حصص + انتهاء صلاحية + تنظيف دوري |
| روابط خارجية خبيثة في نص الدعوة | تعطيل الروابط في النصوص الحرة، أو تحذير قبل الخروج |

### التصعيد

```
مستوى 1 — آلي:  حد معدل، Turnstile، حظر مؤقت
مستوى 2 — إشارة: نمط مشبوه → علامة للمراجعة (لا إيقاف تلقائي)
مستوى 3 — بلاغ:  مراجعة بشرية خلال 24 ساعة
مستوى 4 — إجراء: إيقاف دعوة (فوري) / إيقاف حساب / حظر
مستوى 5 — قانوني: تعاون مع جهات إنفاذ عند الحاجة
```

⚠️ **مبدأ:** لا إيقاف آلي كامل بلا مراجعة بشرية. إيقاف دعوة عرس بالخطأ ليلة الحفل
ضرر لا يُصلَح باعتذار. الأتمتة تُشير، والبشر يقررون.

## 8. الخصوصية

### مبادئ

1. **جمع أقل ما يمكن.** كل حقل يُسأل: هل نحتاجه فعلاً؟
2. **لا تتبّع للزوار.** لا كوكيز، لا IP، لا بصمة جهاز.
3. **الشفافية.** سياسة خصوصية واضحة بلغة مفهومة، بالعربية والإنجليزية.
4. **التحكم للمستخدم.** تصدير، حذف، إيقاف — كلها متاحة ذاتياً.

### ما نجمعه ولماذا

| البيانات | السبب | الاحتفاظ |
|----------|-------|----------|
| بريد المستخدم | المصادقة والتواصل | حتى الحذف |
| كلمة المرور (hash) | المصادقة | حتى الحذف |
| محتوى الدعوة | الخدمة | حتى الحذف |
| اسم الضيف + رد | خدمة RSVP لصاحب الدعوة | 90 يوماً بعد الحفل |
| هاتف الضيف (اختياري) | تواصل صاحب الدعوة | 90 يوماً بعد الحفل |
| hash الزائر (يومي) | عدّ الزوار الفريدين | 90 يوماً، غير قابل للربط بعد اليوم |
| الدولة، فئة الجهاز | إحصاءات مجمّعة | 90 يوماً |
| hash عنوان IP | حد المعدل ومنع الإساءة فقط | 24 ساعة |

### ما **لا** نجمعه

❌ عناوين IP خام · ❌ كوكيز تتبع · ❌ بصمة جهاز · ❌ موقع دقيق للزوار
❌ سجل تصفح · ❌ سكربتات إعلانية طرف ثالث · ❌ Facebook/Google Pixel

### التحليلات بلا كوكيز

```
visitor_hash = SHA256( daily_salt ‖ client_ip ‖ user_agent ‖ invitation_id )
```
- `daily_salt` يُولَّد عشوائياً كل 24 ساعة **ولا يُخزَّن دائماً**.
- بعد انقضاء اليوم، لا يمكن لأحد — بما فينا — عكس الـ hash أو ربط زيارات عبر الأيام.
- النتيجة: عدّ فريد دقيق ضمن اليوم، بلا أي قدرة على التتبع.

📄 [ADR-0009](adr/0009-cookieless-analytics.md)

### حقوق المستخدم

| الحق | التنفيذ |
|------|---------|
| الوصول | `GET /api/v1/me/export` → JSON كامل |
| الحذف | `POST /api/v1/me/delete` → 30 يوم سماح ثم حذف صلب |
| التصحيح | تعديل الملف الشخصي |
| النقل | تصدير JSON قياسي |
| الاعتراض | لا تسويق افتراضياً؛ إلغاء اشتراك في كل بريد |

**بيانات الضيوف:** لا يملك الضيف حساباً، لكنه يستطيع طلب حذف رده عبر رابط في صفحة التأكيد
أو بمراسلة الدعم.

## 9. الاستجابة للحوادث

### التصنيف

| المستوى | التعريف | الاستجابة |
|---------|---------|-----------|
| **P0** | تسريب بيانات، اختراق، الموقع ساقط بالكامل | فوري، كل الأيدي |
| **P1** | ثغرة حرجة، دفع معطّل، الدعوات لا تُعرض | < 1 ساعة |
| **P2** | ثغرة عالية، تدهور جزئي | < 4 ساعات |
| **P3** | ثغرة متوسطة | < 3 أيام |

### دليل التعامل مع تسريب بيانات

```
1. احتواء     — عزل، إبطال كل الجلسات، تدوير الأسرار
2. تقييم      — ما البيانات؟ كم مستخدماً؟ منذ متى؟ (من السجلات)
3. إصلاح      — سدّ الثغرة، نشر، تحقق
4. إخطار      — المتضررون خلال 72 ساعة، بلغة واضحة، بما يجب فعله
5. تحليل      — مراجعة بلا لوم أشخاص، إجراءات وقائية
6. توثيق      — تقرير كامل محفوظ
```

⚠️ **حالة خاصة:** إن سُرّبت بيانات ضيوف، فالمتضررون ليسوا مستخدمينا — لا نملك وسيلة
لإخطارهم مباشرة. الإجراء: إخطار أصحاب الدعوات المتأثرة **بوضوح تام** ليخطروا ضيوفهم.
هذا سبب إضافي لتقليل ما نخزّنه عن الضيوف من الأساس.

**مصفوفة IDOR — مولّدة آلياً:**
```typescript
for (const endpoint of MUTATING_ENDPOINTS_WITH_RESOURCE_ID) {
  test(`${endpoint} يمنع الوصول عبر المستأجرين`, async () => {
    const a = await createUserWithInvitation();
    const b = await createUser();
    const res = await callAs(b, endpoint, { id: a.invitationId });
    expect(res.status).toBe(404);        // 404 لا 403
  });
}
```
التوليد الآلي يعني: **نقطة نهاية جديدة تُختبَر تلقائياً** — لا يمكن نسيانها.

## 11. قائمة تحقق ما قبل الإطلاق

```
□ كل الترويسات الأمنية مطبّقة ومُختبَرة
□ CSP بلا unsafe-inline / unsafe-eval
□ لا أسرار في المستودع أو تاريخه (gitleaks نظيف)
□ كل الأسرار في مدير أسرار، منفصلة لكل بيئة
□ HTTPS مفروض + HSTS preload
□ حدود المعدل مفعّلة ومُختبَرة على كل نقطة عامة
□ 2FA إلزامية على كل حسابات الموظفين
□ تجريد EXIF مُتحقَّق منه بصور حقيقية تحوي GPS
□ SVG مرفوض — مُختبَر
□ مصفوفة IDOR خضراء بالكامل
□ سجل التدقيق يعمل ويُختبَر
□ سياسة الخصوصية والشروط منشورتان بالعربية والإنجليزية
□ آلية البلاغ وإيقاف الدعوة تعملان (مُختبَرتان فعلياً)
□ النسخ الاحتياطي مُختبَر باسترجاع حقيقي
□ لا ثغرات Critical/High مفتوحة
□ خطة الاستجابة للحوادث موثّقة ومعروفة للفريق
□ اختبار اختراق خارجي مكتمل والنتائج معالجة
```
