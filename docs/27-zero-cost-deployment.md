# 27 — تشغيل المكدّس المجاني: إجراء واحد لكل بند

> **المرحلة الحالية: تشغيل، لا تطوير.**
> الكود والاختبارات والهجرة انتهت عند `730319a`. ما تبقّى ليس شيئًا يُكتب، بل
> حسابات تُنشأ وقيم تُنقل ونشرة تُثبَت حيّة.
>
> **لا يُلمس الكود في هذه المرحلة** — ولا `apps/worker` ولا BullMQ ولا
> `MediaQueue` ولا `render.yaml` ولا [ADR-0022](adr/0022-render-deployment-topology.md)
> ولا Argon2 ولا مسار معالجة الوسائط. الرجوع عن المعمارية الجديدة يبقى
> `MEDIA_DISPATCH=queue` وإعادة نشر.
>
> الأساس: [ADR-0023](adr/0023-inline-media-processing-zero-cost.md) ·
> [docs/25](25-zero-cost-launch.md) · [docs/26](26-zero-dollar-migration-analysis.md)

## ١. Neon — قاعدة البيانات

| | |
|---|---|
| **ماذا تنشئ** | مشروع Neon، Postgres **16**، منطقة أوروبا (الأقرب إلى Frankfurt) |
| **من أين تأخذ القيمة** | Dashboard → Connection Details → **Pooled connection** — المجمَّعة لا المباشرة: خدمة تنام وتستيقظ تفتح اتصالات جديدة باستمرار، والمنفذ المباشر ينفد قبل المجمَّع بكثير |
| **أين تضعها** | **مرّتان، وبقيمة واحدة:** ① GitHub → Settings → Secrets and variables → Actions → `FREE_STACK_DATABASE_URL` ② Render → `zfaf-web-free` → Environment → `DATABASE_URL` |
| **كيف تتحقّق** | Neon → SQL Editor → `SELECT version();` يعيد `PostgreSQL 16.x`. ولا تتحقّق من الرابط بلصقه في أي مكان آخر: هو كلمة مرور |

> **لماذا مرّتان:** الهجرات تُشغَّل من GitHub Actions (لا يوجد `preDeployCommand`
> على النسخة المجانية)، والتطبيق يقرأ من Render. **نفس القيمة حرفيًا** — قاعدتان
> مختلفتان تعنيان تطبيقًا يعمل على مخطّط لم تُطبَّق عليه هجرة.

## ٢. Upstash — Redis

| | |
|---|---|
| **ماذا تنشئ** | قاعدة Upstash Redis، منطقة أوروبا، **Eviction: disabled** |
| **من أين تأخذ القيمة** | Dashboard → Details → **`rediss://…` (بروتوكول Redis)** — وليس `UPSTASH_REDIS_REST_URL`. التطبيق يستخدم `ioredis` وهو بروتوكول TCP لا REST |
| **أين تضعها** | Render → `zfaf-web-free` → Environment → `REDIS_URL` |
| **كيف تتحقّق** | Upstash → Data Browser يفتح ويقبل `PING`. والتحقّق الحقيقي في §٧ |

> **لماذا Upstash وليس Render:** Render رفضت بكلماتها —
> `cannot have more than 1 free tier Key Value instance` — والخانة المجانية
> الوحيدة على هذا الحساب مشغولة بمشروع آخر، **وحذف مورد مشروع آخر ليس خطوة نشر**.
> وهو الأفضل هنا أصلًا: يحفظ على القرص، فإعادة التشغيل لا تكلّف عدّادات الحدّ
> المعدّل ولا مخزن المشاهدات. وقد صار كافيًا لأن عامل BullMQ رحل: عامل خامل كان
> يكلّف ١٥٩ ألف أمر يوميًا مقابل حدّ ٥٠٠ ألف شهريًا
> ([docs/25 §٥-أ](25-zero-cost-launch.md)).
>
> **`Eviction: disabled` ليس تفضيلًا.** حدّ معدّل يتوقّف عن العدّ لأن المخزن طرد
> مفاتيحه هو حدّ لا يحدّ شيئًا — ويفشل مفتوحًا بلا أن يقول.

## ٣. Backblaze B2 — التخزين

| | |
|---|---|
| **ماذا تنشئ** | حاوية `zfaf-media` · **Private** · ثم مفتاح تطبيق مقصور عليها وحدها |
| **من أين تأخذ القيمة** | Application Keys → Add a New Application Key → «Allow access to Bucket(s): `zfaf-media`» → Read and Write. تظهر `keyID` و`applicationKey` **مرّة واحدة فقط**. وفي Bucket Details: `Endpoint` (مثل `s3.eu-central-003.backblazeb2.com`) |
| **أين تضعها** | Render → `zfaf-web-free`: `STORAGE_ENDPOINT` = `https://<endpoint>` · `STORAGE_ACCESS_KEY_ID` = keyID · `STORAGE_SECRET_ACCESS_KEY` = applicationKey. وفي `zfaf-config-free` (موجودة أصلًا في المخطّط) تحقّق أن `STORAGE_REGION` تطابق منطقة الحاوية — القيمة `auto` تصلح لـ R2 ولا تصلح لـ B2 |
| **كيف تتحقّق** | §٧-٤: رفعة حقيقية من المتصفّح. لا تختبرها بـ`curl` — المسار الذي يفشل هو مسار المتصفّح |

### ٣-أ. سياسة CORS — **خطوة إلزامية، وأكثر ما يُنسى**

الرفع يتمّ من متصفّح العميلة **مباشرةً إلى الحاوية**. بلا CORS يفشل الطلب في
المتصفّح **ولا يظهر شيء في أي سجلّ على الإطلاق** — لا في Render، ولا في Sentry،
ولا في B2. تبدو كعطل في المنتج وهي إعداد ناقص ([docs/22 §٧-أ](22-deployment-render.md)).

على الحاوية: اسمح بـ `PUT` و`GET` و`HEAD` من الأصل `https://zfaf.app` (وأصل
`*.onrender.com` أثناء التجربة)، مع الرؤوس التي يرسلها التوقيع المسبق.

**التحقّق:** افتح صفحة الباني على النشرة، ارفع صورة، وراقب لسان Network. طلب
`PUT` بحالة 200 = صحيحة؛ `CORS error` = السياسة ناقصة. ولا تكمل §٧ قبل أن تنجح.

## ٤. Resend — البريد

| | |
|---|---|
| **ماذا تنشئ** | حساب → Domains → إضافة نطاق الإرسال → إضافة سجلّات **SPF وDKIM وDMARC** في Cloudflare DNS → انتظار «Verified» |
| **من أين تأخذ القيمة** | API Keys → Create → صلاحية **Sending access** فقط |
| **أين تضعها** | Render → `MAIL_RESEND_API_KEY`. و`MAIL_FROM_ADDRESS` في `zfaf-config-free` يجب أن يكون **على النطاق الموثّق نفسه** |
| **كيف تتحقّق** | Resend → Domains تقول `Verified` للسجلّات الثلاثة. والتحقّق الحقيقي في §٧-٢ |

> بلا نطاق موثّق تصل رسالة التفعيل إلى المهملات أو لا تصل، **وكل تسجيل جديد يقف
> عند هذه النقطة** — التطبيق لا يفتح حسابًا قبل تفعيل البريد.

## ٥. Render — الأسرار

الخدمة موجودة ومربوطة بمجموعتَي المتغيّرات. ما ينقص هو القيم.

### ٥-أ. تسعة لا يُقلع بدونها

| المتغيّر | من أين | أين |
|---|---|---|
| `DATABASE_URL` | §١ | على الخدمة |
| `REDIS_URL` | §٢ | على الخدمة |
| `STORAGE_ENDPOINT` · `STORAGE_ACCESS_KEY_ID` · `STORAGE_SECRET_ACCESS_KEY` | §٣ | `zfaf-secrets` |
| `MAIL_RESEND_API_KEY` | §٤ | `zfaf-secrets` |
| `SESSION_SECRET` | `openssl rand -base64 48` | `zfaf-secrets` |
| `TOTP_ENCRYPTION_KEY` | `openssl rand -base64 48` — **قيمة مختلفة** | `zfaf-secrets` |
| `CRON_SECRET` | `openssl rand -base64 48` | `zfaf-secrets` |

`SESSION_SECRET` و`TOTP_ENCRYPTION_KEY` **يجب أن تختلفا، والتطبيق يرفض الإقلاع
إن تساوتا**: تدوير سرّ الجلسات عمل روتيني، وتدوير مفتاح TOTP يوقف كل مُصادِق
مسجَّل دفعةً واحدة. و`CRON_SECRET` إلزامي هنا تحديدًا لأن `MEDIA_DISPATCH=inline`،
ومهمّة `redrive-media` هي وحدها ما يعوّض إعادة محاولة BullMQ — فالتطبيق يرفض
الإقلاع بدونه ([ADR-0023 §٤](adr/0023-inline-media-processing-zero-cost.md)).

### ٥-ب. خمسة تُقلع بدونها، ولكلٍّ ثمن

| المتغيّر | ما يُفقَد بدونه |
|---|---|
| `CDN_ZONE_ID` · `CDN_API_TOKEN` | مفتاح الإيقاف (D8.5) يوقف الدعوة عند الأصل، والنسخ المخزّنة على الحافة تعيش حتى انتهاء TTL |
| `SENTRY_DSN` | الأخطاء في السجلّات فقط، بلا تجميع ولا تنبيه |
| `HEALTH_CHECK_TOKEN` | `/api/health/deep` يعطي حكمًا عامًّا ولا يسمّي المكوّن المعطوب |
| `TURNSTILE_SECRET_KEY` | لا تحقّق بشري على النماذج العامة |

**التحقّق من §٥ كلّها:** حاول النشر. `parseEnv` يفحص البيئة عند الإقلاع ويرفض
الناقصة **ويسمّي المتغيّر في السجلّ**. رسالة رفض واضحة أفضل من إقلاع صامت بقيمة
خاطئة — ولا تعالج الرفض بتخمين، بل بقراءة الاسم الذي طُبع.

## ٦. GitHub Actions — الهجرات

| | |
|---|---|
| **ماذا تشغّل** | `Actions` → **Free stack — migrate** → Run workflow، واكتب في الحقل اسم القاعدة التي تستهدفها |
| **ما الذي يجري** | `prisma migrate deploy` ← `db:templates` ← **`db:templates` مرّة ثانية** |
| **كيف تتحقّق** | التشغيل أخضر، والخطوة الثالثة لا تُغيّر شيئًا. ثم في Neon: `SELECT count(*) FROM templates;` **أكبر من صفر** |

> `db:templates` ليست بذرة تطوير. مكتبة القوالب تعيش مرّتين بالضرورة — ملفّات في
> المستودع، وصفوف تثبّت الدعوة نسخةً منها مدى حياتها ([ADR-0005](adr/0005-published-snapshot-versioning.md))
> — وهذه الخطوة هي الوحيدة التي تنقل الأولى إلى الثانية. بدونها الجدول فارغ،
> واللوحة لا تعرض قالبًا، و**لا تستطيع أي عميلة إنشاء دعوة إطلاقًا**.
>
> والترتيب مُلزِم: **الهجرات قبل النشر.** كود جديد على مخطّط قديم عطل، والعكس
> أسوأ.

## ٧. النشر وإثبات الحياة

### ٧-١. النشر واليقظة الأولى

Render → `zfaf-web-free` → Manual Deploy → الالتزام `730319a`.
(`autoDeploy: no` مقصود: [docs/14 §4](14-cicd-and-deployment.md) يضع بشرًا أمام
الإنتاج.)

أوّل طلب بعد بناء أو بعد نوم يستغرق **٣٠–٦٠ ثانية**. هذا ليس عطلًا؛ هذا ثمن
النسخة المجانية.

### ٧-٢. الفحص الآليّ للقراءة فقط

```bash
pnpm verify:deployment https://zfaf-web-free.onrender.com
```

لا يُسجّل دخولًا ولا يكتب شيئًا: صحّة، وسبر عميق، و**توجيه اللغات D9.1 خلف وسيط
Render الحقيقي** — وهو السؤال الذي لا يستطيع أي مشغّل محلّي الإجابة عنه — ورؤوس
الأمان، وغياب `x-powered-by`.

```bash
E2E_BASE_URL=https://zfaf-web-free.onrender.com \
  pnpm --filter @zfaf/web exec playwright test locale-routing.spec.ts
```

**فقط الأطقم التي لا تكتب.** أي طقم يسجّل دخولًا أو ينشر سيكتب في قاعدة إنتاج،
وهذا ليس اختبارًا بل حادثة.

### ٧-٣. مؤقّت Cloudflare

```bash
cd infra/cloudflare/cron
npx wrangler deploy
npx wrangler secret put CRON_SECRET        # نفس قيمة §٥-أ حرفيًا
```

**التحقّق:** `npx wrangler tail`، ثم من Cloudflare شغّل الجدول يدويًا. السطر
المتوقّع `[cron] sweep-media → 200`. أما `→ 404` فمعناه أن السرّ لا يطابق ما في
Render — لا أن النقطة غير موجودة.

> ⚠️ **لا تضع مؤقّت ping لإبقاء الخدمة مستيقظة.** يحرق ٧٥٠ ساعة Render و١٠٠
> ساعة-حوسبة Neon معًا، والنتيجة تعليق كل شيء حتى الدورة التالية — أسوأ بكثير من
> إقلاع بارد.

### ٧-٤. الاختبار الحقيقي الوحيد: رحلة بشرية كاملة

بالترتيب، على النشرة الحيّة، من هاتف:

| # | الخطوة | ما يُثبته |
|---|---|---|
| ١ | تسجيل حساب | القاعدة والجلسات وArgon2 |
| ٢ | وصول بريد التفعيل | §٤ كلّها |
| ٣ | تسجيل دخول | Redis والحدّ المعدّل |
| ٤ | إنشاء دعوة | §٦ — مكتبة القوالب |
| ٥ | **رفع صورة، مع تشغيل ساعة توقيت** | §٣ وCORS و**`MEDIA_DISPATCH=inline`** |
| ٦ | نشر | التصيير والتخزين |
| ٧ | فتح الرابط كضيف | الصفحة العامة والحافة |
| ٨ | ردّ الضيف | RSVP |
| ٩ | ظهور الردّ في اللوحة | الدائرة مكتملة |

**الخطوة ٥ هي الحُكم على هذا المكدّس بأكمله.** القياس الوحيد المتاح اليوم يقول
١٫٠٢ ثانية معالج لصورة ١٢ ميغابكسل وذروة ١٦١ ميغابايت — **على أنوية كاملة**.
وعُشر المعالج على Render ليس استقراءً خطّيًا موثوقًا، ولا يعرفه إلّا هذا القياس.
سجّل الرقم الفعلي.

- أقلّ من ~١٥ ثانية: مقبول لرفعة أمام مؤشّر تقدّم.
- أطول من ذلك بوضوح: القرار عندئذٍ عمل تجاريّ لا هندسيّ — إمّا قبول البطء، أو
  عامل `starter` بـ`$7` والرجوع إلى `MEDIA_DISPATCH=queue`. **المسار الثاني
  محفوظ وجاهز، ولهذا بالضبط لم يُحذف.**

### ٧-٥. المؤشّر الذي يُقرأ أسبوعيًا

`redrive-media` يجب أن يعيد **صفرًا** في الحالة الطبيعية. رقم غير صفري متكرّر
يعني أن الترميز يفشل بانتظام، و`redriven` هو **عدد الصور التي كانت ستُفقد**.

## ٩. قيود إنتاجية معروفة — مسجَّلة، لا «منتهية»

هذه ليست بنودًا مؤجَّلة في قائمة عمل. هي **خصائص هذا المكدّس**، وتبقى صحيحة
مهما اكتمل ما سبقها.

### ٩-١. لا استعادة نقطة-زمنية (PITR) — ⛔ الأخطر

لا طبقة مجانية في هذا المكدّس تعطي استعادة إلى لحظة بعينها. حذف خاطئ أو تلف
منطقي في قاعدة تحمل دعوات عملاء **لا مسار للتراجع عنه**.

**ما يعنيه عمليًا:** مقبول لتجربة رائدة ببيانات محدودة وتوقّعات معلنة. **غير
مقبول كمعمارية إنتاج نهائية إذا كانت البيانات حقيقية ومهمّة.**

**متى يُرفَع:** أوّل عميلة تدفع، أو أوّل بيانات لا تحتمل الضياع — أيّهما أسبق.
عندها تصير نسخ Neon الاحتياطية المدفوعة، أو قاعدة مُدارة بـPITR، **شرطًا لا
تحسينًا**. ويُتّخذ القرار قبل الحاجة إليه، لأن قيمة النسخة الاحتياطية تُقاس يوم
الحادثة وحده.

### ٩-٢. سلوك ٠٫١ معالج غير مُقاس

كل رقم معالجة في هذه الوثائق قِيس على أنوية كاملة. **لا شيء يثبت بعد أن الخدمة
تبقى ضمن حدودها على نسخة Render المجانية** أثناء ترميز صورة. §٧-٤ الخطوة ٥ هي
القياس، ولا بديل عنها.

### ٩-٣. الإقلاع البارد جزء من المنتج

ضيف يفتح رابط دعوة من واتساب بعد خمول ينتظر ٣٠–٦٠ ثانية. الـCDN يخفّف عن
`/i/[slug]` بعد أوّل زيارة، **ولوحة العميلة غير قابلة للتخزين إطلاقًا** — من
يبني دعوته يدفع الثمن في كل عودة.

### ٩-٤. مورد المؤقّت خارج شبكة الفحص

`infra/cloudflare/cron` لا يدخل أي `tsconfig`: **لا يُفحص نوعيًا ولا يُلَنتَر**،
ولا يمرّ عليه `pnpm verify`. أوّل تحقّق حقيقي منه هو `wrangler tail` في §٧-٣.

### ٩-٥. Render نفسها تقول إن نسختها المجانية «ليست للإنتاج»

قرار عمل واعٍ لمرحلة MVP، لا سهو. مسجَّل هنا حتى لا يُكتشف لاحقًا كمفاجأة.

## ١٠. ما لا يُفعَل في هذه المرحلة

- **لا تعديل كود.** لا `apps/worker`، ولا BullMQ، ولا `MediaQueue`، ولا
  `render.yaml`، ولا ADR-0022، ولا Argon2، ولا معالجة الوسائط.
- **لا خفض لمعاملات Argon2** لأي سبب.
