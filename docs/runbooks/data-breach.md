# Runbook — اشتباه تسريب بيانات

**الشدة:** P0 · **يوقظ:** نعم · **التنبيه:** `privilege_escalation_suspected`

**الخطوة صفر: لا تمسح شيئاً.** أول ردّ فعل غريزي — إعادة تشغيل، تدوير مفاتيح،
حذف جلسات — يمحو الأدلة التي تحتاجها لتعرف ماذا خرج. احفظ أولاً.

## 1. احفظ الأدلة (≤ 10 دقائق)

```bash
# سجل التدقيق: غير قابل للتعديل أو الحذف بمُشغِّل (docs/09 §6) — انسخه كما هو
psql "$DATABASE_URL" -c "\copy (SELECT * FROM audit_logs WHERE created_at > now() - interval '7 days') TO '/secure/audit-$(date +%s).csv' CSV HEADER"

# الجلسات الحيّة وقت الاشتباه
psql "$DATABASE_URL" -c "\copy (SELECT id, user_id, created_at, last_used_at, user_agent FROM sessions WHERE revoked_at IS NULL) TO '/secure/sessions-$(date +%s).csv' CSV HEADER"
```

`audit_logs` لا تحمل عناوين IP خام ولا بيانات ضيوف — بالتصميم (ADR-0009،
docs/15 §2). هذا يعني أن التسريب نفسه يحمل أقل مما قد يُخشى، ويعني أيضاً أن
التحقيق يعتمد على `ip_hash` والمقارنة بالتساوي لا على قراءة عنوان.

## 2. أوقف النزيف

بالترتيب، والترتيب مقصود:

```sql
-- 1. أنهِ جلسات الحساب المشتبه به وحده أولاً
UPDATE sessions SET revoked_at = now() WHERE user_id = '<suspect>' AND revoked_at IS NULL;
```

2. إن كان حساب موظف: أنزل الدور إلى `support`، ثم إلى `customer`. **لا تحذف
   الحساب** — الحذف يأخذ سجل ما فعله معه.
3. دوّر الأسرار المكشوفة (§4).
4. إنهاء جلسات الجميع خطوة أخيرة لا أولى: تُخرج كل عميل وتُنتج عاصفة دعم،
   ولا تفعل شيئاً لم تفعله الخطوة الأولى إن كان النطاق معروفاً.

## 3. حدّد النطاق

```sql
-- ماذا لمس هذا الفاعل؟
SELECT action, resource_type, count(*) FROM audit_logs
 WHERE actor_id = '<suspect>' AND created_at > now() - interval '30 days'
 GROUP BY 1,2 ORDER BY 3 DESC;

-- هل حاول أحد إضعاف المصادقة الثنائية؟
SELECT * FROM audit_logs WHERE action LIKE 'two_factor.%' ORDER BY created_at DESC LIMIT 50;
```

الأسئلة التي تحتاج إجابة قبل أي إعلان: **أي بيانات، لأي مستخدمين، خلال أي
نافذة، وهل خرجت فعلاً أم بقيت مقروءة داخلياً.**

## 4. تدوير الأسرار — والترتيب حرج

| السرّ | الأثر | ملاحظة |
|-------|-------|--------|
| `SESSION_SECRET` | كل الجلسات تنتهي | مقبول، وروتيني |
| `TOTP_ENCRYPTION_KEY` | **كل مصادقة ثنائية تتوقف** | لا تدوّره ارتجالاً. يتطلب خطة إعادة تسجيل لكل موظف، وإلا فقد الجميع الوصول إلى `/admin` معاً |
| `STORAGE_*` | الروابط الموقّعة تبطل | أعد إصدار المفاتيح قبل التبديل |
| `CDN_API_TOKEN` | إزالة الحافة تتوقف | مفتاح الإيقاف يعتمد عليه |
| `DATABASE_URL` | يتطلب نافذة | آخر ما يُدوَّر |

## 5. الإفصاح

هذا قرار قانوني لا هندسي. اجمع الوقائع، ولا تعِد ولا تنفِ شيئاً قبل مراجعة
قانونية. سياسة الخصوصية المنشورة تقول ما نقوله للمستخدمين — اقرأها قبل الكتابة،
وتأكّد أن ما تعلنه يطابقها.

## 6. ما تقوله الوثائق ويجب أن يبقى صحيحاً

سياسة الخصوصية تدّعي: لا عناوين IP للزوار، ولا كوكيز تتبّع، وحدف الحساب فعلي.
كل ادّعاء منها يقابله اختبار قائم (M9). إن كشف الحادث خلاف ذلك، فالخلل ليس في
الحادث وحده بل في الادّعاء — وتصحيحه جزء من الإجراء.
